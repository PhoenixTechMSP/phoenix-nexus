# Changelog

## 2.0.0-alpha.1 - Phoenix Nexus (ITAM + CMDB + SAM)
### Added
- **Licence**: Community is released under AGPL-3.0-only (`LICENSE`), with a commercial licence available (`COMMERCIAL.md`).
  Community files: `CODE_OF_CONDUCT.md`, issue and pull request templates, private vulnerability reporting in `SECURITY.md`,
  public `ROADMAP.md` (Community / Pro split).
- **Numbered database migrations** with an automatic backup before each upgrade (`ptx.db.pre-v<N>-<date>.bak`, last 5 kept),
  one transaction per migration, and a refusal to start on a database newer than the application. See `UPGRADING.md`.
- **CI/CD** (`deploy/CICD.md`): `develop` deploys to UAT, `main` to production after manual approval, image published to
  ghcr.io, automatic rollback, smoke test after each deployment. Release workflow on version tags (`RELEASING.md`).
### Fixed
- `multer` upgraded from 1.x to 2.x (1.x is deprecated and has published vulnerabilities in upload handling). Import behaviour is unchanged.
- Upgrading from a very old database crashed at startup: SQLite refuses `ADD COLUMN ... UNIQUE` (`users.oid`). The column is now
  added first and a unique index created separately.

### Added (earlier in this alpha)
- **CMDB** (`/api/cmdb`, page CMDB): configuration items fed one-way from the asset lifecycle
  (ITAM to CMDB, never the reverse), relationships stored only in the CMDB, archived (not deleted)
  when an asset is retired. Existing instances are reconciled at startup (idempotent).
- **SAM** (`/api/sam`, page SAM): software products, entitlements and assignments, with the licence
  position (entitled minus consumed), status per product (compliant, oversized, limit reached,
  over-deployed, no entitlement), savings identified, compliance exposure and renewals within 90 days.
  The contract metric decides what consumes a licence (per agent or per asset) and is enforced server-side.
- `categories.equipment_class` (Nominative / Infrastructure) and an `integration_events` outbox table.
- Demo data: `scripts/seed-dummy-data.js` and `scripts/seed-sam-demo.js` (fictional, idempotent,
  renewal dates relative to today).
- Test suite (`node --test server/test/*.test.js`, no new dependency) and real-browser scenarios
  (`scripts/e2e/run.sh cmdb|sam`, Playwright, temporary database).

- **Phoenix logo** on the login page, in the header and as the favicon. Two colours: the brand red
  (`#C00000`) on light surfaces and a lighter red (`#E5484D`) on dark ones, because the brand red only
  reaches 2.7:1 on the dark header and login card (WCAG asks 3:1 for graphics) while the lighter red
  reaches 4.4 to 4.6:1. The stroke is thickened on small sizes (the source line is 12 px thick, which
  becomes a 0.5 px hairline at header size). Images are generated by `scripts/brand/make-assets.py`
  from `scripts/brand/phoenix-logo-source.png` (2.9 to 19 KB each instead of 60 KB).

- `.gitignore` (secrets, SQLite databases and their WAL/SHM files, `node_modules`, `data`, `dist`) and two
  tests that fail if git ever tracks `.env`, a database or `node_modules`. The first public commits had
  none of this: a `git add .` had published `.env`, `data/ptx.db` and 7,470 `node_modules` files.

- **Public demo deployment** (`deploy/`): Docker Compose with Caddy (automatic HTTPS), `DEPLOY.md` runbook,
  update and nightly-reset scripts. `DEMO_MODE=1` shows shared demo accounts on the login page, a banner, a 28-day
  synthetic history so the dashboard and forecast are not empty, and **disables file imports** (the `xlsx` library
  has a known vulnerability: nobody should be able to upload on a public instance).
- **Security hardening**: production refuses placeholder or short `JWT_SECRET` values (the value in `.env.example` and the old
  compose default were public); login attempts are rate-limited (8 failures per account and address, 40 per address,
  per 15 minutes) and `TRUST_PROXY` makes that work behind a reverse proxy; security headers; mistyped login input is a
  400 instead of a 500.
- **Test suite**: 143 server tests (API smoke over every read route and both Excel exports, security, demo mode, real
  process startup, translations, deployment files, client API helper) and five real-browser suites (`npm run test:e2e`):
  a crawl of every page in 3 languages, 2 themes and 3 roles, business flows, demo mode, CMDB and SAM.
  `scripts/smoke.mjs <url>` checks any deployed instance with Node alone. GitHub Actions (`.github/workflows/ci.yml`) runs
  everything on each push.

### Fixed
- **The Forecast page was broken**: `/api/events/forecast` returned 500 (`ambiguous column name: department_id`) and the page
  swallowed the error and showed nothing.
- **A wrong password showed no message**: the API helper treated the 401 of a failed login as an expired session and reloaded
  the login page, erasing the error.
- **The server never started on Windows**: the "is this the main module" test compared `import.meta.url` to
  `file://` plus the path, which can never match a Windows path (`C:\...`). It now uses `pathToFileURL`.
- Adding an agent with a duplicate badge failed silently (no error handling in the page).
- A failed Excel export (server error, expired session) was saved as a `.xlsx` file containing JSON; it now shows an error.
- Import silently turned `in_use` into `available` (the status normaliser stripped the underscore).
  Both the classic and the guided importer now read `in_use`, `in use` and `IN-USE`.
- API errors no longer leak SQLite table/column names (`UNIQUE constraint failed: ...`): shared helper
  in `server/lib/errors.js` applied to every route that returned the raw message.
- `server/index.js` no longer starts listening on import, so the app can be tested.
- A guided-import dry run can no longer write anything, CMDB reconciliation included.

### Changed
- **Renamed the product to Phoenix-Nexus** (formerly Site Asset Manager): interface, page title,
  package (`phoenix-nexus` 2.0.0-alpha.1), Docker image/container/service, installers and documentation.
  Kept on purpose so existing installations upgrade with no migration: the database file `ptx.db`, the
  Windows service `PTXFleet`, the `ptx` system user in the image and the `ptx_token` browser key.
  Docker upgrade from a version before 2.0: run `docker compose down` first (the container name changed).
- The README no longer calls the asset inventory a "CMDB": it is the ITAM module, the CMDB is its own module.
- Excel inventory snapshot is now `phoenix-nexus-inventory-<date>.xlsx` (was `site-cmdb-<date>.xlsx`).
- All em-dashes replaced by plain hyphens across code, pages and documentation.
- Header spacing is tighter below 1200 px so that, logo included, the header still fits on one line
  down to 1060 px (it needed 1070 px before the logo existed).
- Amounts in the SAM page follow the language chosen in the app, not the browser locale.

### Security
- `xlsx` (SheetJS from npm) has known high-severity advisories with no npm fix: restrict who can
  upload spreadsheets or move to the vendor distribution before exposing the import to untrusted users.

## [1.6.1] - Automatic Windows update discovery

### Fixed
- `UPDATE-WINDOWS.bat` now recognises the current folder as the existing
  installation when update files were copied over it. No target path is
  required; `.env`, `data`, `logs` and backups remain untouched.
- Separate-folder updates still discover their target through the Windows
  service, with clearer status and error messages.

## [1.5.0] - Guided import + dark theme

### Added
- **Guided CSV/Excel import wizard** with live column mapping: pick which file
  column feeds each asset/agent field, ignore columns, set fixed values, split
  combined cells (e.g. `PTX-0406 / 356966281361586` into `asset_code` and
  `serial`), and map extra columns to notes. Includes dry-run simulation,
  rejected-row preview, and saved mapping profiles per file signature.
- **Dark theme** inspired by Phoenix Tech: near-black background with warm
  orange accents. Toggle in the top bar and on the login page; choice is
  persisted and respects system preference by default.
- **Silent Windows update script** (`UPDATE-WINDOWS.bat`) that backs up the
  database and client dist, redeploys the new version, and restarts the
  `PTXFleet` service with automatic rollback on failure.

### Changed
- Import endpoints are now additive: legacy `POST /api/import/assets`,
  `/api/import/ptx` and `/api/import/agents` remain available; new
  `/api/import/preview` and `/api/import/commit` routes power the wizard.

## [1.4.0] - Site-wide CMDB

### Added
- **Generic asset model** replacing the PTX-only table: `categories`
  (`code`, `name`, `kind` = `IT` / `OT` / `BUSINESS`, `consumable`) and
  `assets` (`asset_code`, `serial`, `label`, `category_id`, `department_id`,
  `status`, `quantity`, `min_quantity`, `location`, repair fields,
  `last_operator_id`). Existing PTX rows and their events are migrated
  automatically into the PTX category on first start.
- **18 seeded categories** (PTX, laptop, desktop, monitor, printer, phone,
  radio, network, PLC, sensor, CCTV, conveyor/BHS, vacuum, trolley, tool,
  cloths, PPE, cleaning supplies) and site departments (General, Operations,
  Warehouse, Sales, HR, Cleaning, IT, Maintenance).
- **Category & department administration** (`/api/categories`,
  `/api/departments` CRUD) with new Admin tabs.
- **Asset CRUD from the Inventory page** with filters by type, category,
  department and status.
- **Consumable stock operations**: `POST /api/assets/:code/consume` and
  `/restock`, low-stock alerts on the dashboard and in the Excel export.
- **Generic repair follow-up**: `POST /api/assets/:code/repair-send` and
  `/repair-return` with ticket and vendor (replaces the earlier PTX-only
  repair endpoints, which remain available through the legacy `/api/ptx`
  alias).
- **Reporting by period** (`day`, `week`, `month`, `year`) filterable by
  asset type and department; per-type, per-category and per-department
  breakdowns.
- **Generic import** `POST /api/import/assets` (optionally
  `?category=CODE`); `/api/import/ptx` still works and forces the PTX
  category.
- **Asset history** endpoint `GET /api/assets/:id/history`.
- Full EN / FR / NL translations for all new screens.

### Changed
- Renamed the product to **Site Asset Manager (CMDB)**.
- `/api/ptx` is kept as an alias of `/api/assets` for backward compatibility.
- Excel snapshot renamed to `site-cmdb-<date>.xlsx` with summary sheets by
  type, status, department, category and consumables stock.

## [Unreleased]

### Added
- **Vendor repair tracking** on PTX: `bac_ticket`, `bac_sent_at`,
  `bac_returned_at`, `bac_notes` (idempotent `ALTER TABLE`) - later
  superseded by the generic `repair_*` columns on the `assets` table.
- **Responsible operator** persisted on every PTX: `last_operator_id`
  and `last_status_change_at` updated on check-out, check-in, PATCH,
  repair-send and repair-return - the field manager who last touched
  the device is always retrievable without scanning the events log.
- **New endpoints** (superseded, see "Changed" further above):
  - `POST /api/ptx/:code/repair-send` - flag a PTX as sent for
    repair or replacement (status `repair`, records ticket + notes).
  - `POST /api/ptx/:code/repair-return` - mark the PTX back from
    repair (status `available`, `defective` or `retired`).
  - `GET /api/events/fleet-export.xlsx` - live aggregated snapshot
    workbook: summary by status, summary by department (Available /
    In use / Defective / In repair / Lost / Stolen / Retired / Total),
    and a Fleet sheet listing every PTX with its current agent,
    department, repair state and last operator.
  - `GET /api/events/fleet-snapshot` - JSON version of the same
    snapshot for dashboards or auto-refresh tables.
- **Event types** `repair_send` and `repair_return` added to the
  `ptx_events.event_type` CHECK constraint (new installs).
- **Logs page**: additional "Export fleet snapshot" button.

### Migration notes
- Existing v1.0/v1.1 databases already have the `ptx_events.event_type`
  CHECK constraint from the initial schema and will reject
  `repair_send` / `repair_return` inserts. Run a one-shot migration to
  recreate the table without the constraint (see `ARCHITECTURE.md`
  -> *Extending event types*) or drop and recreate on a fresh install.

- Documentation set rewritten in English (README, PREREQUISITES,
  INSTALL, CONFIGURATION, ARCHITECTURE, API, CONTRIBUTING, SECURITY).

## [1.1.0] - 2026

### Added
- **i18n**: English (default), French, Dutch. Per-user language preference
  persisted in the `users.language` column with a CHECK constraint.
- **Language switcher** component available in the top bar of every page.
- **Microsoft Entra ID SSO** via OpenID Connect (`openid-client`):
  - New `/api/sso/{status,login,callback}` endpoints.
  - Auto-provisioning with configurable default role
    (`SSO_DEFAULT_ROLE`, defaults to `pending`).
  - Domain allowlist via `SSO_ALLOWED_DOMAINS`.
  - MFA / phishing-resistant auth delegated to Entra Conditional Access.
- **Admin → Users** console: create, update, disable, delete, reset password.
  Last active admin protected against deletion.
- **Users table**: `oid`, `status`, `language`, `last_login_at` columns
  added through idempotent `ALTER TABLE` migrations.

### Changed
- README, INSTALL and `.env.example` updated to document SSO and i18n.
- `Login.jsx` now shows the SSO button when `SSO_ENABLED=true` and handles
  the `?sso=ok` / `?sso=pending` callback query parameters.

### Security
- SSO users start in `pending` state by default - no access until an admin
  approves them.
- Client secret handling documented (rotation cadence, expiry limits).

## [1.0.0] - Initial release

### Added
- Local email/password authentication with bcrypt + JWT.
- Three-role model: `admin`, `manager`, `staff`.
- SQLite schema for `departments`, `users`, `agents`, `ptx`, `ptx_events`
  with WAL mode and foreign key enforcement.
- QR-code scanning of PTX labels (`PTX-XXXX / <IMEI>`) with camera and
  manual fallback.
- Check-in / check-out flow with autocomplete on both agents and PTX.
- Excel / CSV import for PTX and agents with duplicate-IMEI detection and
  downloadable conflict report.
- Excel export of the event log.
- Analytics dashboard: KPIs, per-department usage, 30-day activity trend,
  status distribution.
- Multi-stage Dockerfile and `docker-compose.yml` - single container,
  single SQLite file.
- `scripts/first-admin.js` CLI (idempotent UPSERT).
- `scripts/backup.sh` hot-backup with 30-day retention.
- Deployment guide for Docker, systemd, Windows Server + NSSM,
  Nginx and IIS reverse proxies.
